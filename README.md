Este repositório contém o resumo das lições aprendidas durante o desenvolvimento do lab na DIO o que é e como funciona: O Azure é a plataforma de computação em nuvem da Microsoft, que oferece serviços a pessoas e empresas. Funciona como um data center virtual para hospedar sites e sistemas, guardar arquivos e banco de dados, cria redes seguras na numvem, usa IA e analise de dados. O serviço corresponde como "alugar computadores de ponta". Em resumo, é um conjunto de ferramentas na internet que substitui ou complementa servidores e softwares que antes ficavam só dentro da empresa. Conceitos de nuvem: usar recursos de TI (servidores, bancos, redes,aplicativos) pela internet em vez de depender apenas do computador local ou do data center próprio. Funciona com modelos diferentes de serviços como SAAS (software como serviço, usando programas prontos, teams, outlook etc)/ iaas-você aluga máquinas virtuais, redes e discos. É como alugar um “computador gigante” na nuvem. (serviço redes, discos ou maquinas virtuais), paas:você usa uma plataforma pronta para rodar aplicativos sem precisar gerenciar servidores. Ex.: Azure App Service (plataforma como serviço (hospedar apps sem cuidar de servidores). Oss modelos de implantação podem ser em nuvem publica (azure, aws, google cloud), nuvem privada (servidores exclusivos da empresa) e nuvem híbrica (mistura dos dois). Os beneficios em adiquirir esse tipo de serviço, são: agilidade, redução de custos, segurança, disponibilidade etc. Principais benefícios: Escalabilidade Crescer ou diminuir recursos conforme a demanda. Ex.: Loja online que aumenta servidores na Black Friday e reduz depois. Elasticidade Ajuste automático e quase imediato de recursos. Ex.: Um app que aumenta poder de processamento só quando recebe muitos acessos. Confiabilidade e alta disponibilidade O Azure tem datacenters no mundo inteiro, garantindo redundância. Isso significa menos chance de ficar fora do ar. Segurança Camadas de proteção física, digital e políticas de acesso (MFA, RBAC). Mais investimento em segurança do que a maioria das empresas poderia ter sozinha. Previsibilidade de custo Paga-se só pelo uso (modelo “pay-as-you-go”). Também existem reservas (contratos de 1 a 3 anos que reduzem custos). Agilidade e inovação Permite testar novas ideias rapidamente sem precisar comprar hardware caro. Ex.: testar IA no Azure Cognitive Services sem precisar ter um supercomputador. Modelo de responsabilidade compartilhada A Microsoft cuida da infraestrutura física. Você cuida dos dados e configurações. Isso simplifica a vida de quem usa. Arquitetura e serviços Azure: regiões: locais no mundo onde ficam os datacenters (Brasil, EUA, etc). Areas disponiveis ou Availability Zones : zonas independentes dentro de uma região para garantir alta disponilidade. Grupo de recursos e subinscrições: formas de organizar os recursos criados;. Grupos de gerenciamento: camadas acima para organizar varias contas, subscrições. Principais serviços do Azure: Compute (processamento): Máquinas Virtuais, App Service, Azure Functions, Kubernetes (AKS). Armazenamento: Blob (arquivos grandes), Files (pasta de rede), Disk (discos de VM), Queue (filas). Redes: Virtual Network (VNet), VPN Gateway, ExpressRoute, DNS, Load Balancer. Bancos de dados: Azure SQL Database, Cosmos DB, MySQL, PostgreSQL. Ferramentas de desenvolvimento e integração: Azure DevOps, GitHub, Logic Apps IA e dados: Azure Cognitive Services, Machine Learning, Synapse Analytic Segurança: Microsoft Entra ID (antigo Azure AD): identidade e login. RBAC (Role-Based Access Control): dar permissões específicas para usuários/grupos. MFA (Autenticação multifator): login mais seguro (senha + celular, por exemplo). Defender for Cloud: monitora vulnerabilidades e ataques. Princípio Zero Trust: nunca confiar automaticamente, sempre verificar. Governança: Azure Policy: regras para garantir conformidade (ex.: só criar recursos no Brasil). Resource Locks: travar recursos para evitar exclusão acidental. Tags: etiquetas para organizar recursos por projeto/departamento. BluePrints: modelos para aplicar governança de forma padronizada. Custos: Modelo Pay-as-you-go: pagar pelo uso (como conta de luz). Reserved Instances: desconto por contratar 1–3 anos. Pricing Calculator: simular custos antes de criar recursos. TCO Calculator: comparar custos da nuvem x infraestrutura local. Azure Advisor: recomenda como economizar.

Entendendo sobre Segurança e Identidade na Azure:
O Azure cria uma identidade digital (entra ID), controla o acesso com segurança (SSO, mfa, rbac, acesso condicional, zero trust) e protege seus recursos na nuvem através do defender, contoles de identidade e autorização, tanto para funcionarios, parceiros de negocios e clientes. Microsoft entra ID (antigo Azure AD): é o serviço de identidade e acesso do Azure e funciona como uma "lista de usuários e permissões concedidas" da organização, permitindo que funcionários, parceiros de negocio ou até clientes se autentiquem através de login em aplicativos e serviços da microsoft como officee 365, teams, azure e outros. Microsoft entra Domain services: é como ter um active directory na nuvem, permitindo assim usar recursos tradicionais do AD como ingressar maquinas em domínio, políticas em grupo, sem precisar de serviços locais para isso. Para empresas que já usam AD no escritorio, auxilia para migrar para nuvem. SSO: é o login unico, apenas com email corporativo ou pessoal o usuário acessa varios sistemas como outlook, sharepoints, teams etc, sem precisar digitar senha toda hora. MFA:é a camada extra de segurança, exige duas ou mais provas de identidade como por exemplo: numero do celular, token, biometria etc, evitando que um possível invasor acesse a conta mesmo que roube a senha Acesso a pessoas fora da organização: é possivel convidar parceiros ou clientes para acessar seus sistemas de forma segura (colaboração externa), exemplo: fornecedor acessa o portal de pedidos sem que ele tenha o mesmo acesso que um funcionario tem. Microsoft Entra External ID (b2b e B2C): B2B: para parceiros, fornecedores (permite convidar usuários externos para acessar seus aplicativos. B2C: para clientes finais, permitindo que usuários usem contas pessoais para acessar seu aplicativo. Microsoft Defender pra Nuvem: é o serviçoo de monitoramento e proteção, que detecta ameaças, ataques e mas configurações em servidores, redees, bancos de dados e apliações. Dá recomendações para deixar tudo mais seguro. Funciona como um "antivirus da nuvem" Autenticação x Autorização: no caso da autenticação, serve para confirmar quem a pessoa é, podendo ser biometria, senha, login, pode ser multifator, token etc. No caso da autorização: ela define o que voce pode fazer deopis de autenticado (acesso a arquivos, sistemas, configurações etc).Os tipos de autorização RBAC: permissões baseadas em funçoes, papéis desempenhados/ABAC: permissões baeadas em atributos (cargo, departamento, horario e localização)/PBAC: baseado em políticas configuradas pela empresa, como regra exemplo: apenas diretores podem acessar contratos acima de x valor. / Acesso Condicional no Azure: junta autenticação com autorização e decide automaticamente se permite ou bloqueia acesso dependendo do contexto. Confiança Zero: Modelo de segurança que parte do princípio: nunca confie sempre verifique. Mesmo dentro da rede da empresa, o usuário precisa se autenticar e provar que está autorizado. Proteção completa: é a combinação de todas as camadas (identidade segura - entra ID e MFA), acesso inteligente (sso, acesso condicional, rbac), monitoramento constante (defender para nuvem), política zero trust Os recursos do Azure são os elementos que protegem e gerenciam as maquinas virtuais, banco de dados, armazenamento (blobs, arquivos, discos etc), redes virtuais, aplicativos web e apis).
Otimizando Custos no Azure_resumo_lab:
A gestão de custos ou gerenciamento de custos no Azure representa o conjunto de ferramentas e praticas que ajudam as empresas e tambem usuarios a controlar, monitorar e ajustar os gastos na nuvem.Essa atividade envolve planejamento, monitoramento e ajustes para garantir que recursos sejam usados de forma mai eficiente possivel. Os fatures que afetam os custos na Azure são: 1- região: o mesmo recurso pode custar mais ou menos depenndendo da região, isso acontece por questões de impostos, disponibilidade e demanda. (regiões como o Brasil, são mais caras que os Estados Unidos). 2- Tipos de recursos: maquinas virtuais, bancos de dados, armazenamento e rede tem precificação propria. Quanto mais capacidade ou desempenho, maior o custo. 3- modelo de cobrança: pay as you go (sob demanda): paga apenas pelo uso (hora, minuto, dependendo do recurso). Pode excluir recursos a qualquer momento, o custo é mais alto em comparação aos demais modelos. Indicado para testes rapidos, projetos curtos e emrpesas que não sabem ainda a demanda real que terão / Reservado (reserved instances): voce reserva o recurso por 1 ou 3 anos. Os descontos podem chegar a 70% comparado ao pay as you go. É menos flexivel, voce precisa assumir o compromisso de uso. É indicado para sistemas que ficam sempre ligados como banco de dados, ERP's etc, empresas que já conhecem a demanda e precisam de estabilidade/ Spot Instances: são mais baratos,usam capacidade ociosa do Azure, podem ser interrompidos a qualquer momento quando o Azure precisar dos recursos. É indicado para processos que podem ser interrompidos como simulações, calculos, testes e renderização, workloads não criticos. 4-tempo de uso: se um recurso fica ligado por 24 horas por dia, o custo sera maior do que se ele for usado apenas algumas horas. 5- trafego de rede: entrada de dados é normalmente gratuita, já a saída de dados é cobrada. Os custos são cobrados da seguinte forma: de forma consumida, voce paga pelo que usar. Basicamente custo total = preço por unidade x quantidade consumida + custos adicionais de rede/licenciamento. Exemplo: uma VM custa R$ 0,50 por hora. Se fica ligada 24 horas por dia x 30 dias, o custo sera 0,50 x 24x30= 360,00 . Além disso, o portal do Azure https://azure.microsoft.com/pt-br/pricing/calculator/, através da caculadora de preços ajuda a prever esses valores. As marcas (tags) no Azure: as tags são rotulos em formato "par nome valor" atribuidos aos recursos. exemplo: nome = departamento valor= financeiro. As marcas organizam os recursos em categorias lógicas, facilitam relatórios de custos (saber quanto determinado departamento gastou) e permitem politicas de govenança (exemplo: exigir que toda VM tenha uma tag "projeto"). AS TAGS NÃO SÃO HERDADAS automaticamente pelos recursos dentro de um grupo de recursos, elas preisam ser aplicadas individualmente ou de forma automatizada com Azure Policy. Marketplace no Azure: é um catalogo de soluções e serviços de terceiros (além da Microsoft) que podem ser adquiridos e integrados diretamente no Azure. Como exemplo: firewalls de segurança (fortnet, palo alto), softwares empresariais (sap, oracle), aplicações de análise de dados. Os custos do Marketplace são ADICIONADOS à fatura do Azure. Custos por região: o mesmo recurso em regiões diferentes podem variar bastante. Exemplo: VM D2s V3 em EAST US: 70/MES enquanto que VM D2s V3 no Brazil South, pode custar 95/mes. As vezes vale mais a pena odar em uma região mais barata, desde que atenda aos requisitos de latência e conformidade. Cálculo do custo total: o Azure oferece ferramentas proprias: 1- calculadora de preços que estima quanto voce gastara antes de criar os recursos, permite simular cenários. 2- calculadora TCO (CUSTO TOTAL) que compara os custos de infraestrutura on premisses (servidores locais) com os custos equivalentes no Azure, ajuda a mostrar a economia de migrar para a nuvem.3-Auzre Cost management +Billing: ferramenta dentro do portal que mostra relatorios, tendencias e permite configurar alertas de gasto.

Serve para:garantir que novas assinaturas ou grupos de recursos sigam padrões de segurança e governança e automatizar a criação de recursos com compliance pré-definido. são componentes de um Blueprint:Artefatos: Políticas do Azure: regras de compliance/Papéis (RBAC): quem tem acesso a quê/Grupos de Recursos: para organizar recursos/Modelos ARM: infraestrutura como código/Assinatura: onde o Blueprint será aplicado. Os benefícios são: padronização de ambientes/ redução de erros humanos / compliance e governança consistentes / facilita auditorias. Azure Policy: Ferramenta que aplica regras e efeitos sobre recursos do Azure.Garante que recursos criados ou existentes sigam políticas corporativas. Você define uma policy definition e depois aplica a policy a uma assinatura ou grupo de recursos . Os tipos de efeitos de políticas são:Deny:impede a criação ou alteração do recurso que não cumpre a política / audit:registra uma violação, mas não bloqueia / append: adiciona automaticamente propriedades a recursos / DeployIfNotExists: cria recursos automaticamente se não existirem . Os beneficios são: Compliance automática, previne uso incorreto ou inseguro de recursos, permite relatorios e monitoramento continuo. Bloqueios de Recursos: Ferramenta que protege recursos específicos ou grupos de recursos contra alterações ou exclusão acidental. Os tipos são: Delete: Impede que o recurso seja excluído / Permite leitura e alterações. // read only: Impede qualquer modificação e permite apenas leitura. Serve para proteger recursos críticos como bancos de dados, VMs de produção, redes e evita problemas por ações humanas ou scripts automaticos. Os bloqueios não impedem alterações por administradores com permissões elevadas, mas fornecem aviso e camada extra de proteção. É possível aplicar bloqueios a: assinaturas, grupos de recursos ou recursos individuais.

O Azure Powershell é uma das ferramentas de implantação de recursos do Azure: é um conjunto de módulos que permitem gerenciar recursos via powershell (linguagem da microsoft). Funciona como uma ponte entre o computador e o Azure. Servie para automatizar tarefas, criar, atualizar e excluir recursos sem precisar usar o portal. Tendo sua funcinalidade voltada para automação e gerenciamento de recursos com scripts. Um exemplo de configuração: instalar módulo Az: autenticar com connect AZaccount, tipo: CLI baseada em powershell, pode ser usada por administradores windows e automação avançada. SErvie para criar maquinas virtuais, redes, banco de dados, gerenciar grupos de recursos, alicar po´liticas, tags e permissões, atuomatizar tarefas repetitivas para economizar tempo. A instalação: no windows ja vem instalado, no linux ou mac, precisa baixar atraves do link: https://aka.ms/powershell. As vantagens do Azure Powershell são: rapido para criar recursos em massa, muito util pra engenheiros de nuvem e administradores, pode ser usado localmente ou em scripts no azuredevops. o Azure Cloud Shell: e um ambiente de linha de comando hospedado no navegador. Ja vem configurado com Azure CLI e PowerShell. Serive para executar comandos e scripts do Azure sem instalar nada no computador, gerenciar recursos de qualquer lugar com apenas um navegador. Exemplo: ciar um grupo de recursos via cloud shell: AZ group create - noame meugrupocloudshell-location eastus. Ao abrir o cloud shell, escolher entre Bash (linux) ou powershell (windows). A interface de linha de comando (azure CLI): É uma ferramenta para gerenciar recursos do Azure via terminal, serve para criar,atualizar e monitorar recursos do azure usando scripts ou comandos. Funciona no windows, linux e mac. Um exemplo, criando uma VM: AZ vm create - resource-group meu grupo - name minha VM - image ubuntuLTS - size standard-B1s. CLI é mais multiplataforma, power shell é mais integrado ao windows. Os Grupos de Recursos (Resource Groups): são conteiners logicos para organizar recursos relacionados no azure. Servem para facilitar gerenciamento, permissões, monitoramento e cobrança de recursos. Exemplo: colocarVM, banco de dados e rede no mesmo grupo. Recuros podem ser movidos entre grupos, mas so podem pertencer a um grupo de cada vez. Exemplo de grupo de recursos: az group create - name meu grupo - location eastus A VNET1 e uma rede virtual do Azure: rede privada que conecta recursos entre si, como uma LAN em nuvem. Permite comunicação segura entre VMS, banco de dados e serviços. Isola recursos da internet publica. Um exemplo: criando uma vnet com subrede: az network vnet create - resource group meu grupo - name vnet1-address-prefix 11.0.0.1/15-subnet name subrede1...Obs: voce pode conectar VNets entre regiões ou com sua rede local usando VPN ou ExpressRoute. O Azure ARC é uma plataforma que permite gerenciar recursos fora do Azure (on-premises ou outras nuvens) como se estivessem no Azure. Servem para aplicar governança, politicas e monitoramento centralizado em servidores, clusters kubernetes e banco de dados externos. Exemplo: registrar um servidor local no azure arc para aplicar azure policy de segurança. Ideal para empresas com infraestrutura hibrida ou multicloud. My Dashborard (meu painel) é um painel personalizavel dentro do portal da azure, serve para visualizar recursos, alertas e custos em uma unica tela.Para conifgurar clique em paineis + novo painel, arraste blocos de metricas, graficos ou recursos e salve ou compartilhe. Ferramentas de monitoramento do Azure: Recursos e Serviços /Assitencia no Azure:
Azure Advisor: é uma ferramenta gratuita que analisa suas configurações e uso do Azure. Fornece recomendações práticas para melhorar desempenho, confiabilidade, custo e boas práticas operacionais. Serve para identificar problemas antes que eles aconteçam. Sugere ajustes para economia de custos ou melhora desempenho. Exemplo: Pode sugerir desligar VMs subutilizadas ou alterar para um tipo de VM mais barato, tambem indica quando aplicar atualizações de segurança ou amentar a redundância de serviços.
Integridade do Serviço do Azure : Service Health
É uma ferramenta que informa o estado dos serviços do Azure que é utilizada. Mostra interrupções, manutenções programadas e problemas regionais. Permite agir rapdidamente quando há problemas e evita surpresas, ajudando no planjemanento de manutenção. Exemplo: Voce pode receber um aviso que a VM em Brazil South terá manutenção. Assim, poderá mover cargas críticas para outra região temporariamente.
Azure Monitor:É um serviço completo para monitorar recursos e aplicativos no Azure.Coleta logs, métricas e telemetria. Tem como componentes: Azure Log analytics: Coleta e analisa grandes volumes de logs e métricas, permitindo criar consultas avançadas para identificar problemas. Alertas do Azure Monitor: Dispara avisos automáticos quando algo não está funcionando conforme esperado, exemplo: enviar um e-mail quando a CPU de uma VM passa de 80%. Application insights: Monitoramento focado em aplicativos, mede desempenho, disponibilidade e detecta erros em apps web, exemplo: detectar que uma página de login está com alto tempo de resposta.
